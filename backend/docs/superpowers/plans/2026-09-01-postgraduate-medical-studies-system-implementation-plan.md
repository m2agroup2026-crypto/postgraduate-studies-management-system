# خطة تنفيذ نظام إدارة الدراسات العليا

**المرجع:** `docs/superpowers/specs/2026-09-01-postgraduate-medical-studies-system-design.md`
**الجهة:** كلية الطب – جامعة أسيوط
**التاريخ:** 1 سبتمبر 2026
**التقنية:** Python / Django / PostgreSQL / Django Templates / RTL

## مبادئ التنفيذ

- تنفيذ رأسي تدريجي: كل مرحلة تنتج وظيفة قابلة للتشغيل والاختبار.
- كتابة اختبار فاشل أولًا لكل قاعدة عمل، ثم أقل كود يمرره، ثم إعادة التنظيم.
- عدم تخزين أرقام اللائحة داخل الكود؛ تستخدم بيانات إعدادات مؤرخة.
- عدم حذف سجل أكاديمي نهائيًا.
- كل إجراء حساس يمر بدورة مراجعة ويظهر في سجل الرقابة.
- لا تُستخدم بيانات طلاب حقيقية في التطوير المحلي أو الاختبارات الآلية.
- كل مهمة تنتهي باختبارات وCommit مستقل صغير.

**الملفات:** `pyproject.toml`, `manage.py`, `config/*`, `.env.example`, `.gitignore`, `README.md`

2. فصل إعدادات التطوير والاختبار والتشغيل.

**التحقق:** تشغيل فحص Django واختبار صفحة صحة بسيطة دون أخطاء.

- لا يبدأ التشغيل الرسمي مع عيب مانع أو جوهري مفتوح.

## بوابات الجودة قبل كل إصدار

يجب أن تمر الأوامر التالية أو ما يعادلها:

```bash
python manage.py check --deploy
pytest
ruff check .
ruff format --check .
python manage.py makemigrations --check --dry-run
```

ويجب كذلك:

- عدم وجود هجرات مفقودة أو أخطاء صلاحيات.
- عدم وجود بيانات شخصية داخل المستودع أو عينات الاختبار.
- نجاح اختبار الاستعادة الأخير.
- نجاح فحص التباين والطباعة العربية.
- توثيق تغييرات قاعدة البيانات وقواعد اللائحة.

## نقطة بدء التنفيذ

يبدأ التنفيذ بالمرحلة 0 ثم 1 و2 و3 بالترتيب. بعد اكتمال ملف الطالب والبحث والقيد، تُعرض نسخة تشغيلية أولى على المستخدم قبل بناء بقية الوحدات. هذا يقلل مخاطر اكتشاف مشاكل تجربة الاستخدام بعد اكتمال النظام كله.
